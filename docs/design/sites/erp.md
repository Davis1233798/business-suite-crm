# LedgerWorks 進銷存財 開發範本

狀態：已完成本地 UI/UX 實作；實際驗證範圍見 [實作紀錄](../IMPLEMENTATION.md)。路徑：`/erp`。

## 模板來源與選型

原始參考：[本地 sap DESIGN.md](../references/sap/DESIGN.md)。來源版本見 [manifest](../manifest.json)。

SAP 的企業框架、單據表格與財務資訊層級最符合採購、庫存和帳款。

## 頁面骨架

產品標題與操作 → 庫存／帳款摘要 → 單據與庫存表 → 調撥／收付款 → 進階單據工作區

桌面：工作內容與操作側欄並排，主要內容可收縮（min-width: 0）；表格在自己的容器水平捲動。平板：摘要與工作區適度換行。手機：單欄，操作摘要接續內容，不遮住表單及確認按鈕。

## 元件清單

- `DocumentTable`
- `WarehouseSelector`
- `TransferForm`
- `InvoicePayment`
- `TrialBalance`

## 視覺規則

- 主操作 `#0057d2`；底色 `#f5f6f7`；內容表面 `#ffffff`。
- 數字使用 tabular-nums；正文 14–16px；次要文字至少 12px；觸控操作至少 44px。
- 頁首平面灰框架；表格表頭淺灰；控制項 8px、面板 12px 圓角；不以陰影堆疊資訊。
- 使用共用語意色及可見鍵盤焦點。字體採系統中文字體；不得依賴來源品牌專有字型。

## 業務保留條件

保留採購審核收貨、銷售出貨、調撥、收付款、傳票和期間關帳；所有金額靠右且使用等寬數字。

## 實作定位

`app/erp/page.tsx; app/erp/advanced.tsx`

從頁面區域設定 data-site="erp"，於該區域定義 CSS custom properties；共用按鈕／表單讀取區域 token。禁止用全域色碼取代把其他站台改色。所有 API、資料模型、金額規則與角色處理沿用現有實作。

## 驗收條件

- 360、768、1440px 寬度逐一截圖；無頁面級橫向溢出，表格可在容器捲動。
- 鍵盤可操作分頁、表單和主要操作；焦點可見；標籤、錯誤訊息可被輔助工具辨識。
- 載入、無資料、API 錯誤、送出中、成功及唯讀拒絕均有清楚呈現。
- 一般文字對比至少 4.5:1；大型文字與控制項邊界至少 3:1；狀態必須搭配文字。
- 走完本範本業務保留條件中的核心流程；執行 TypeScript、既有相關測試與正式建置。

## 開發指令範本
